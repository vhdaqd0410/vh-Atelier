## 一、音源如何同步到其他电脑

### 现状

音源脚本存放在 `lxserver/data/users/source/_open/` 下（`.js` 文件）+ `order.json`（排序）。
这个目录**已排除在仓库与更新之外**（否则会覆盖你已配好的源）。

所以：**新电脑装完插件后，音源是空的，需要自己导入。** 有三种办法。

### 方案 A：服务器托管（推荐，最省事）

你已经部署了服务器版。把音源**只配在服务器上**，所有电脑的插件都切到「服务器」模式：

```
你的电脑 A ─┐
你的电脑 B ─┼─→ 服务器 :17899（音源配在这里）→ 五平台
你的电脑 C ─┘
```

- **优点**：配一次，所有机器生效；换机器/重装插件都不用重配；音源更新只改服务器。
- **代价**：所有请求走服务器（搜索元数据很轻，播放走平台直链不占服务器带宽）。
- **操作**：面板「来源」切到「服务器」，填服务器地址。

这是**最符合你需求的做法**——`data/users/source/` 只维护一份。

### 方案 B：本地 + 一次性导入（离线可用）

每台电脑的插件目录下配自己的音源。分发方式：

1. 把 `lxserver/data/users/source/_open/` 整个目录打包（zip）
2. 新电脑解压到 插件的 `lxserver/data/users/source/_open/`
3. 面板里重载即可

- **优点**：不依赖服务器，离线可用
- **代价**：每台机器要手动做一次；音源更新要重新分发

**可以做成一键**：我给你写一个 `导入音源.bat`，双击把音源包解压到正确位置。

### 方案 C：插件内置「音源包」导入

在音乐聚合面板加一个「导入音源包」按钮，选 zip 后自动解压到 `data/users/source/_open/`。

- **优点**：不用教使用者找目录
- **代价**：要写一点代码（约 50 行），且要处理"已有源不覆盖"的逻辑

### 我的建议

**优先方案 A**（服务器托管），因为它把你的"配一次"变成真的只配一次。
如果某些机器要离线用，再配方案 C 做补充。

## 二、原生面板方案（替代 iframe）

### 为什么考虑原生

现在面板是**iframe 嵌 lxserver 的 Web 播放器**。它的优缺点：

| 优点 | 缺点 |
|---|---|
| 功能完整（歌单/歌词/队列/音质） | 视觉风格是播放器的，不是插件的 |
| 随 lxserver 升级自动获得新功能 | 无法和插件的音乐库/导入 PR 打通 |
| 零维护成本 | 深色模式跟随插件主题较难（跨源限制） |

### 原生面板要做什么

**第一步：复用 lxserver 的 REST API**（不用改它）

| 用途 | 接口 |
|---|---|
| 搜索 | `GET /api/music/search?source=wy&name=关键词&type=song&limit=20` |
| 取直链 | `POST /api/music/url` body: `{songInfo, quality}` |
| 歌词 | `GET /api/music/lyric?source=wy&songmid=ID` |
| 榜单 | `GET /api/music/leaderboard/boards` |
| 热搜 | `GET /api/music/hotSearch` |

**第二步：面板布局**

```
┌─ 音乐聚合 ─────────────────────────────────────┐
│ [本地/服务器 ▾]  ● 已就绪    [↻] [↗外部]        │
├────────────────────────────────────────────────┤
│ 🔍 [搜索框..................] [搜索]  [榜单▾]   │
│ 平台： ●网易云 ○QQ ○酷我 ○酷狗 ○咪咕 ○全部     │
├────────────────────────────────────────────────┤
│ 结果列表                                        │
│ ┌──────────────────────────────────────────┐   │
│ │ ♪ 屋顶 · 周杰伦、温岚      [试听][下载][→PR]│   │
│ │ ♪ 晴天 · 周杰伦            [试听][下载][→PR]│   │
│ └──────────────────────────────────────────┘   │
├────────────────────────────────────────────────┤
│ 播放器（可选，复用扒歌面板的波形播放器）         │
└────────────────────────────────────────────────┘
```

**第三步：和插件打通**（这是原生的真正价值）

1. **下载到音乐库**：调 `POST /api/music/download`，落到 `collect/bgm/music/`，音乐库面板自动可见
2. **插入时间轴**：复用现有的 `vcInsertPayload` / `meImportTreePlanStr` 机制（语音克隆/人声分离都在用）
3. **拖进 PR**：CEP 官方 DnD（`com.adobe.cep.dnd.file.0`），和音效库/人声分离一致
4. **试听用 wavesurfer**：与扒歌/人声分离一致，带波形

**第四步：换源切换**

每个平台一个筛选 chip，搜索时调对应 `source` 参数；也可以做"全部"并发搜索后合并去重。

### 工作量与风险

| 部分 | 工作量 | 风险 |
|---|---|---|
| 搜索 + 结果列表 | 1 天 | 低（接口已验证） |
| 取直链 + 试听 | 0.5 天 | 中（直链有时效，要处理过期重取） |
| 下载到音乐库 | 0.5 天 | 低（复用现成机制） |
| 插入时间轴 / 拖拽 | 0.5 天 | 低（复用现成机制） |
| 歌单/歌词（可选） | 1 天 | 低 |

**总计约 3–4 天**，风险主要在**音源直链的时效性**——它是临时地址，播放前要现取。

### 建议的演进路径

**不要一次做完。** 我建议：

1. **保留 iframe**（它已经能用，是完整功能）
2. **原生面板做成第二个 tab 或面板下半区**，只做三件事：搜索、试听、导入到音乐库
3. 用着顺手再扩展（插入时间轴、歌单、歌词）

这样两边并存：想用完整功能切 iframe，想和插件打通用原生区。
